# 技術Stack
- PostgreSQL
- C# + ASP.NET Core + EF core + bcrypt + JWT(JwtBearer)
- Next.js + MUI + tailwind
# 機能概要
1. CRUD + search + aggregate
2. calendar
3. Todo list
4. server notify
5. dashboard comment

# 運用方法

## 上記構造を正本としてJSONファイルを作る

```text
JSONの役割

- 実装単位の要求を機械可読JSONとして発行する。
- JSONはコード生成物ではなく、Agentへ渡す実装契約とする。
- JSON発行前に定義補完しなければならない場合はOwnerに必ず報告する。
- JSONには以下を含める。
  - 実装対象
  - 入力
  - 出力
  - 必須変数
  - 型
  - 参照先
  - 条件
  - 禁止事項
  - 期待値
  - 必要なtest case
- AgentはJSONに存在しない仕様を独自補完しない。
- 補完による語彙や概念の捏造は禁止。  
- 実装コードはJSONから派生する成果物であり、JSONの代替SSOTにはしない。
- JSONと実装が不一致の場合は、実装を根拠にJSONを逆補完せず、不一致として扱う。
```

## JSONを利用したTestファイル実装
```text
テスト方針

1. JSON Contract Test
   - 必須keyの存在確認
   - 必須変数の欠落確認
   - 型の整合確認
   - 参照先の存在確認
   - 条件・禁止事項の記述確認

2. Implementation Consistency Test
   - JSONに定義された入力が実装されているか確認
   - JSONに定義された出力が返却されるか確認
   - 必須変数・分岐・validator・dispatchの実装漏れを確認
   - JSONに存在しないハードコードや独自仕様の混入を確認
   - 禁止事項への違反を確認

3. Build / Static Test
   - C# build
   - TypeScript type check
   - lint
   - SQL構文・migration整合確認
   - test code自体の実行可能性確認

4. Runtime Test
   - JSONで定義した実値をAPIへ投入
   - 実際のdispatchと動的queryを実行
   - runtime errorが発生しないことを確認
   - HTTP statusだけでなくresponseの実値を期待値と比較
   - DBのinsert/update/delete結果を確認
   - 必要なmutation/historyが期待通り記録されたことを確認

5. Acceptance
   - JSON Contract Test PASS
   - Implementation Consistency Test PASS
   - Build / Static Test PASS
   - Runtime Test PASS
   - 実値結果 == JSONの期待値
   - 全条件を満たした時点で実装完了とする
```
